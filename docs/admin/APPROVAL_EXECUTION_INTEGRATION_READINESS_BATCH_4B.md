## Recommended next batch

Use a separately reviewed **non-activating integration-design batch**, not an activation release. Choose one action family and settle its exact policy, immutable payload schema/provider, target/evidence versions and action-specific no-effect execution plan. Map every legacy HTTP/page/direct-service/CLI path to the eventual same domain guard. Do not expose lower-role endpoints that call broad ADMIN helpers or retain an ungoverned legacy bypass while claiming approval enforcement.

Before implementing any real effect, independently review the execution capability allocation, human assurance, legal-state validator, resource/actor lock ordering, atomic receipt/audit and fault/rollback plan. The synthetic counter logic must never be swapped for a real model update. A real handler must be explicit and action-specific; no client-selected function, arbitrary SQL, generic model updater or generalized Booking status editor.

## Production readiness checklist — all required conditions unresolved or unactivated

- [ ] Real issuer verification, assertion signature/audience/nonce/replay checks, recent MFA TTL, recovery and key lifecycle. PENDING/TEST_VERIFIED/shadow results are not live credentials.
- [ ] Trusted canonical human proofing/deduplication, account-alias correction, investigator/participant/target/prior-reviewer/related-incident lineage and protected provenance. Distinct accounts never count as distinct humans.
- [ ] Live staff-session issuance/expiry/revocation and bigint-safe epoch/policy binding, including suspension, stale grants, in-flight changes and all offboarding writers.
- [ ] Persisted exact case/resource/field/purpose assignments, independent Owner/Borrower channel grants and conflict-aware domain adapters.
- [ ] Explicit product-approved per-action requester/approver/executor roles/capabilities, risk, legal transitions, payload schema, quorum, expiry and emergency policy. Proposed registry `.execute` names confer no rights.
- [ ] Sufficient independently eligible human staffing for requests, reviews, appeals, staff bootstrap and conflicted prior reviewers. The rehearsal's three-human rule is a conservative test choice, not an approved production allocation; insufficient real coverage means hold the action, not use aliases or service agents.
- [ ] Independently protected attributable audit writing and immutable successful-effect receipts; failure and denied attempts must not be mislabeled success. Complete storage outage remains fail-closed.
- [ ] Restricted runtime versus controlled migration/audit DB principals. No runtime schema ownership, arbitrary trigger/function creation, constraint disabling, history editing or SECURITY DEFINER shortcut. Owner/superuser bypass cannot be fixed by application checks alone.
- [ ] Validated immutable payload/reason/rationale/evidence providers, digest/version verification, field-minimized reviewer DTOs, cryptographic provenance where required and no private bodies/secrets/raw GPS in global records.
- [ ] Retention/legal holds, protected archival/pseudonymization and privacy/account-link correction without erasing audit/conflict history. No destructive purge or retention period is assumed approved.
- [ ] One shared, reviewed authorization/domain transaction protocol for every real writer: lock order, revalidation, idempotency, stale/cancel/expiry races, deadlocks/timeouts, cache/external-store consistency, network/ambiguous commit reconciliation and rollback.
- [ ] Complete legacy Admin authorization migration, including direct sanctions/dispute methods, protected media, case helpers, provisioning/import tooling and every route/page/service. `ADMIN OR staffRole` and temporary ADMIN grants for lower roles are forbidden.
- [ ] Independent security review, staging backup/restore and mixed-version rehearsal, explicit later approval to implement/activate a narrow real handler, and a separate reviewed migration before reconsidering ACTIVE/APPROVED/EXECUTED/COMMITTED safeguards.

No production-readiness claim is made. Existing direct legacy actions are **not protected** by this execution foundation. Keep current behavior intact until an explicitly authorized safe cutover covers both routes and underlying services.
