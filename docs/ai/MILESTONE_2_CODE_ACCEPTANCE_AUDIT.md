## Performance audit — hypotheses, not diagnoses

Gateway `lib/local-inference/gateway.ts:34–49`:60s abort, think:false, stream:false, keep_alive0s,8192 context,2048 predicted-token ceiling, temperature0; both English/zh-TW drafts requested even for one output language; one inference/process. Response≤65536 bytes. Builder enforces12000-byte manifest; whole request≤24000 bytes including prompt/schema. These are byte/options bounds, not exact tokenizer guarantees. Server limiter remains6 valid attempts/actor/min and max1000 actor counters. New conversation does not clear it.

Owner latencies25482–41414ms are genuine reported app measurements but do not split loading, prompt evaluation, generation, model unload, UI or network time. `keep_alive0s` can add repeated cold loads; bilingual drafts/schema token count and growing source context can increase work. Apple Silicon memory pressure, exact model digest/quantization, competing work and Ollama/GPU behavior are unmeasured. No causal conclusion or model/timeout/infrastructure change is justified here.

M3 should capture existing app latency, client elapsed time and permitted Ollama duration/counter metadata only through a separately reviewed bounded diagnostic design. Record cold/warm state as unknown unless established; current unload behavior must be recorded. Do not bypass the protected app, enable raw thinking, change keep-alive, reduce validation, silently retry, increase deadlines or select another model to obtain green results.
