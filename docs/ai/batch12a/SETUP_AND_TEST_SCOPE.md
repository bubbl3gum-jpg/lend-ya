# Setup, demonstration and selected verification

The source route is `/admin/ai-case-brief`. It requires an existing **ACTIVE legacy Admin and valid session**, `NODE_ENV=development` and exact independent `HUSTLEN_AI_CASE_BRIEF_DEMO=synthetic-only`. No browser flag or new staff membership authorizes it. The prototype has no model endpoint, real case selector, provider credentials, mutation API, server action or persistent draft/review store. Production refusal occurs in proxy before rendering; the page repeats its gate and current Admin check. All unsupported query selectors are refused. `_rsc` is reserved Next transport only and never selects a case or changes authority.

For repeatable demonstration, run `npm run test:ai-case-brief` with an explicit fresh `MRT_TEST_DATABASE_URL` in private local configuration and a PostgreSQL role able to create/drop its owned disposable target. Do not use an existing application database or relabel its ownership. The existing harness checks effective driver target, database difference, run ownership and cleanup; it creates synthetic users/Admin fixtures only in the new database, exercises actual HTTP/browser routes and saves screenshots/metadata. `MRT_BROWSER_PATH=/usr/bin/chromium` was used here. Connection strings must not enter source, screenshots or logs.

The prototype itself reads no Support/booking data and has no writes. Persistence-changing tests are needed only to authenticate real fixture sessions and prove existing guards and selected case tables remain unchanged. An interactive development reviewer may use the same freshly owned fixture setup and exact gate; do not provision a real privileged account or enable this route in production. Test-created servers/databases are stopped/dropped on completion; the review package does not claim a permanent live demo URL. Independent inspection is available through committed screenshots and real-browser evidence.
