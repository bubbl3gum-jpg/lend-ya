## Effective-value handling and modification requirements

The existing read adapter uses validated `locationSettings`, QR TTL helpers, retention helpers and constant exports; invalid/missing values become an explicit unavailable state. Per-station actual operational values remain in Locations, with no claim that a false flag suspends existing agreed handoffs. Per-account feature allowlists and internal origins/URLs are never exposed. A configured gate remains labelled configured, subject to current server authorization and ownership. Read-only client search/grouping operates only on this already authorized safe DTO.

Every security/custody/GPS/evidence/consent/station/staff/MFA/session/private Support/payment/sanction/approval/infrastructure rule remains outside the new typed registry. Any later change requires exact product ownership, invariants/consumer analysis, reviewed migration/versioning/consistency and appropriate independent approval; current dashboard labels do not authorize it. No generic key-value endpoint exists.
