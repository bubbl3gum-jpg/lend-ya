# Pre-implementation agreement audit

Clean baseline `8528ac146a67bc22d24513fa6dab87fab4058c58` on `feature/durable-owner-studio-batch-13d-r1`; supplied implementation `c3bbfedf4209c1855d2a223a8381b84a132fbf83` and evidence `4e16630e8aafcd6187a3b86f6331438ccf1e9aee` verified ancestors. Separate branch `feature/rental-documentation-agreement-batch-13d-r2`.

`lib/item-studio/service.ts`, its four Prisma models and R1 migration provide real owner-private drafts/photos and immutable owner confirmations, with exact owner/session/development gates, atomic revision events and protected byte endpoints. Confirmation does not publish a listing or share a version. Reuse these immutable facts/media; no new condition-evidence store or AI pipeline.

`app/api/bookings/route.ts` is the authoritative request: authenticated actor, bounded time/station/notes, idempotency key/hash, ACTIVE account/listing/media/moderation checks, station support, price/deposit calculation, overlap and serializable transaction; quote-only branch precedes Booking.create. Frozen request data is on Booking. `components/booking-form.tsx` reviews quotation then submits that exact selection. No borrower documentation version is acknowledged at baseline.

`app/api/bookings/[id]/route.ts` is existing owner acceptance: participant/owner/PENDING checks, then booking/listing locks, active participants, future start/availability/moderation/overlap and guarded transition to CONFIRMED. Replays return original persisted request; no independent agreement authority should duplicate this transition. Cancellation/rejection and later handoff/return/inspection remain existing operations.

`app/listings/[id]/page.tsx` applies existing visibility and booking eligibility; `lib/listing-status.ts` derives availability. Designation cannot bypass any eligibility check. Legacy rows/listings without pilot designation retain old behavior. R1 `agreementAdapter()` deliberately always UNKNOWN; extend the real request/acceptance boundary now authorized by R2, retaining UNKNOWN for historical rows, rather than backfilling facts.

Proposed extension: append-only owner designation events/current pointer; short-lived session-bound server quotation review contexts; nullable immutable context/acknowledgement/acceptance references directly on Booking. Borrower acknowledgement is written only during actual request creation; owner acceptance only during existing PENDING→CONFIRMED transaction. No independently mutable snapshot/acceptance endpoint. Canonical source facts remain immutable R1 version/photo rows. Explicit unselection blocks new pilot requests rather than silently removing acknowledgement requirements; never-designated listings remain legacy.

Media remains private: prospective borrowers need their valid current review context and eligible listing; request/booking participants may retain exact acknowledged media through their booking, regardless of later designation edits. No drafts, other historical versions, private rental evidence, identity documents, Admin/Support bypass or unrestricted URLs. Fresh pickup remains the physical-condition baseline, distinct from owner declaration and agreed information.

A changed designation before submission requires a new quotation/review. A changed designation before acceptance blocks the existing accept operation; no amendment mechanism exists to replace the pending request's acknowledgement. Explicit next step is cancel/reject and a newly reviewed request. Accepted references cannot change with subsequent listing/docs edits. No production cutover, publishing, identity requirement, financial/dispute action or live inference.
