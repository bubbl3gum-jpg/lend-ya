Before implementation:13D has a working transient review only. `lib/item-documentation/service.ts` decodes selected stills using `lib/booking-evidence.ts`, returns bounded deterministic hints, stores nothing. `components/documentation-workspace.tsx` loses drafts on leaving. Reuse its version1 category registry and heuristics, inherited heritage/locale shell, owned DB guard and participant-only comparison; do not replace original listing or rental evidence.

`prisma/schema.prisma` Listing/ListingMedia stores current description/category/condition/accessories and sanitized media; `lib/listing-media.ts` uses disk files and existing eligibility guards. Rental evidence instead uses protected BookingEvidencePhoto bytea, uploader/stage/time and authenticated `app/api/bookings/[id]/evidence/[photoId]/route.ts`. Reuse bytea authorization/storage convention for new private documentation media, with a separate explicitly named source; never insert it as pickup/return evidence. No new public URLs.

New persistence required: owner/listing-scoped editable draft, immutable photo records, owner-confirmed immutable version snapshots (including checklist definition and protected refs), append-only attributed revision events and atomic revision/confirmation constraints. Draft text can be incomplete; confirmation requires complete declarations/views and explicit human confirmation. Both photo-first and manual-first use the same records.

`app/api/bookings/route.ts` freezes quotation/daily/total/deposit/station/dates at request, with idempotency and serializable transaction; `app/api/bookings/[id]/route.ts` owner acceptance locks booking/listing and validates availability. Neither request nor acceptance includes a documentation-version selector, borrower review acknowledgment, material-fact hash or acceptance policy. Therefore neither is evidence both parties agreed to new documentation. A side endpoint selecting the owner's latest version would create a competing agreement authority and could retroactively insert unilateral facts.

**Snapshot blocker:** actual binding requires an approved additive extension to request/quotation and owner acceptance: explicit version/hash shown to borrower, same-proposal acceptance by both parties, transaction/retry/concurrency/cutover policy and obligation-preserving expiry/ownership rules. This batch will deliver a tested no-write adapter returning UNKNOWN/AGREEMENT_EXTENSION_REQUIRED under actual participant checks. It will never label current owner confirmation as rental agreement or backfill old bookings. Fresh pickup remains the physical-handoff condition baseline even after a future agreed-information snapshot exists.

`lib/inspection/service.ts` and the13D comparison reader preserve real return authority, original stage provenance and unclassified historical views. Integration may show owner-authorized current documentation separately and an explicit unknown agreed section; borrowers cannot see unrelated or unagreed private listing drafts/media. Existing Support/staff/AI audits/permissions are not general evidence rights. Existing event models are domain-specific; do not misuse AdminAuditLog to grant administrative authority or store document payloads.

No production publishing, new eKYC/Vision authority, claim/borrower-response persistence, notification-driven deadlines, funds, staff privileges or autonomous operations. All new writes must be development-only in the verified owned disposable database. A narrowly additive migration is justified for durable real persistence; historical migrations and original records remain unchanged.
