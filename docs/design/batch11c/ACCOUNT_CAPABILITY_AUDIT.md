# Batch 11C — account/profile/password capability audit

Baseline: clean `afa1da866936fcfb0f3eb14cca4c78ea70580b18` on `feature/marketplace-home-navigation-batch-11b`; implementation ancestor `5d7101a84c2944d0ad69c4a1e4659fa0af774ce1`, evidence ancestor `d21ebf194f09a610041398d04cc55a6dc4000e7a`. Audited before changing UI. Stage 9 only.

| Capability | Baseline source and actual behavior | 11C treatment |
| --- | --- | --- |
| Profile fields | `prisma/schema.prisma` User has name, email, passwordHash, role/status, verification/trust fields and timestamps. Not all persisted fields are user-editable. | Account UI receives only own name/email and status/authorized-view booleans; no new editable identity/security fields. |
| Display name | `app/api/account/route.ts` PATCH authenticates `getCurrentUser`, validates string/nonblank/raw JS length ≤100, trims it and updates only that actor's name. Registration allows up to 120; account mutation limit remains 100. | Real existing mutation; localized validation, saving/error/retry and dirty state. UTF-16/native maxlength semantics remain, not a new grapheme-count policy. |
| Email | Existing Account page displays current own email. PATCH does not update email; no account email-change or email-verification mutation exists. | Explicit read-only explanation, no fake editing/verification control. |
| Foreign selector | PATCH has no target-user selector; supplied id/userId/query selectors do not choose another actor. | Real tests prove forged target/email/role cannot edit the victim; the current foreign actor can still edit their own name under the unchanged contract. This is not falsely reported as a 403 for ignored keys. |
| Password hashing/login | `lib/auth.ts`, `/api/auth/register`, `/api/auth/login` implement existing scrypt/session behavior. | Unchanged. No new password/security flow. |
| Password change | No authenticated change-password endpoint or account password-change form was found. | Mark unavailable; do not build a shortcut or present a working control. |
| Forgot/recovery | `app/api/auth/forgot-password/route.ts` validates email/phone contact but explicitly says delivery is not configured; no token/notification/reset workflow. Existing auth form calls this stub. | Do not call it working recovery; unchanged outside the localization slice. Account explains unavailability. No reassociation/email-only reset. |
| Own session | `getCurrentUser` checks persisted AuthSession; expired sessions are deleted/denied. Account layout redirects unauthenticated requests to login. | On a real PATCH 401 the mounted form retains the user's draft, shows localized expiry guidance and hides read-only email/status. Fresh Account GET still redirects. No session extension or auth-state fabrication. |
| Admin session overview | `app/admin/account-security/page.tsx`, `lib/admin/own-session.ts` and guards expose minimal own-session timestamps only to ACTIVE legacy Admin. | Existing authorized Admin gets a link. Ordinary account UI does not invent timestamps, device identity or passkey assurance. The target page remains English and guarded. |
| Passkeys | Existing `/admin/security` pilot is development-only; production refusal/association/MFA controls already exist. | Unchanged; locale is not MFA or staff authority. |
| Suspended account | Existing account name PATCH permits own editing with a valid session; marketplace restrictions remain separate. | Preserve exactly; show actual suspended state, test existing edit behavior. No restoration/booking bypass. |
| Activity/trust/public profile | `app/account/activity`, `/account/verification`, `/profile/[id]` use existing own/public data read models and trust/review rules. | Content remains English, explicitly tagged as outside translation coverage; shared shell/nav translates. No historical record/UGC translation. |
| Previous UX | `components/account-settings.tsx` retained text after transport errors and refreshed after save, but stored feedback as English strings and did not distinguish expired session. | Typed feedback IDs translate in place; drafts survive language changes and recoverable errors. Real 500 error reference is shown when valid. Native required validity remains with localized onInvalid feedback. |

No schema/migration, API, auth/session/CSRF, password, email, staff membership, recovery or immutable evidence change. No profile-photo/phone/email-verification feature is invented. Snapshot account information is not continuous assurance; server guards remain authoritative on every request. After expiry, input remains only in the current document; navigating/reloading can discard it, and the UI advises copying it before signing in. No sensitive draft is put in local storage.
