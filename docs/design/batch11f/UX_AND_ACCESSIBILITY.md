# Actual Account Settings corrections and checks

`components/password-change.tsx` adds local Show/Hide controls with field-specific accessible names, aria-controls/pressed and no persisted password visibility. All fields return to hidden on real submit/final completion. Typed values survive language switches; after an actual server attempt credentials are cleared. Client-only validation retains correctable input and focuses the exact invalid field; server error summary receives focus and sits before the fields so the next Tab reaches current password. Real success receives focus and links to the real sign-in flow; unrelated name draft stays selectable while Save is disabled.

`app/heritage.css` uses existing paper/ink tokens and a scoped flexible password-control row; no redesign/new assets. `lib/i18n/catalogues.ts` adds nine English/Traditional Chinese pairs (230 total): six field-specific Show/Hide names, two visible labels and a group label. Credential actions have no particles/sound. Existing System theme, independent motion/sound preferences and form protection remain.

The final browser scenario checks actual 400 wrong-password and 500 injected audit failure, then real committed success; labels, aria-invalid, focused error/success, Tab ordering, hidden/reset values, selectable name draft, six concurrent attempts and strict unexpected-browser-error collection. Only the exact deliberately tested HTTP failures are compared as local expected deltas; other unexpected errors still fail. No shared collector suppression or deadline changes.

Twelve screenshots cover en/zh-TW × light/dark × 1440/820/390 CSS pixels. A separate 640px reflow capture approximates the available width of 1280px at 200%; this is not native browser/OS zoom certification. Tests measure no horizontal overflow, at least 44px visibility targets and >=4.5 contrast for their text. Reduced-motion is tested in an actual browser context. Escape/focus restoration is checked on mobile; outside dismissal is checked on the tablet sheet where an outside region actually exists. Full-screen mobile has no outside region to click. Existing account/navigation suites retain navigation dismissal and forms.

Not certified here: physical iPhone, Safari/WebKit, assistive screen-reader announcements, native zoom, all-site WCAG conformance or low-end hardware. Product-owner visual review remains pending. See SCREENSHOTS.md and `account-security-review.json` for exact automated scope; do not substitute screenshots for real functional tests.
