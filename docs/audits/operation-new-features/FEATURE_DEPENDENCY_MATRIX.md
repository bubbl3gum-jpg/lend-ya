## Database and API contract queue

1. A and B independently submit proposed schemas/contracts without editing shared files: field types, keys, ownership, retention, indexes, idempotency and concurrency cases. Model names above are proposals; no ledger/payment/reset tables are claimed to exist.
2. A specifies token hashing, expiry clock, single-use consumption and request/replay semantics; reset, password write, session revocation and security event must have an approved atomic boundary. Race against existing login/password-change issuers is mandatory coverage. Decide queued mail failure, enumeration resistance and expiry before a real transport.
3. B specifies currency/scale/rounding/caps, immutable policy version and quotation, balanced postings, append-only reversals and external settlement distinction. Stable booking snapshots must survive policy changes/restarts. Dispute, physical return and financial settlement stay separate states.
4. Integrator serializes additive migrations and approved adapters, generates Prisma client per worktree, verifies schema and fresh migration history plus isolated upgrade fixtures. Do not backfill real timestamps, deposits or documentation from 'latest'; destructive/data cutover plans require separate review.
5. All new endpoints need explicit DTOs, authenticated subject/role/Origin rules where applicable, rate limits, bounded inputs, no-store/error policy, transaction and failure postconditions. Reset is unauthenticated by necessity but never grants staff/financial privileges; approved token possession and abuse protections govern it.
