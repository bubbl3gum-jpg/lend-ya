## Audit coverage and architecture

The complete source inventory covers 571 application/component/service/script/test files, 75 Prisma models and 33 migration SQL files. [Every page and API](consolidation-20261102/ENTRY_POINTS.md) has its exact path/method and access family recorded. [SOURCE_INVENTORY.json](consolidation-20261102/SOURCE_INVENTORY.json) records source hashes, exported contracts, imports, environment identifiers (never values), all models/fields, migrations/checksums, package scripts/dependencies and all 139 local/remote refs observed. This scan is exhaustive enumeration, not an assertion that a regex proves authorization. The source-backed family analysis below identifies actual delegated guards and runtime dependencies.

Next.js App Router (`app/`) → server page or route → domain service (`lib/`) → one Prisma/pg PostgreSQL model (`lib/prisma.ts`, `prisma/schema.prisma`). Client components render trusted DTOs and invoke authenticated APIs. `proxy.ts` enforces same-origin mutation protections and independently refuses experimental production paths. `lib/auth.ts` owns hashed database sessions, scrypt password checks and credential-snapshot serialization. A cookie is not a staff capability. `lib/rental-lifecycle.ts` and `lib/meetup/service.ts` coordinate the authoritative Booking row; there is no second custody engine. Local listing media is file-backed; protected rental evidence is DB-backed bytes. Legacy ADMIN and ChatReviewer remain separate from inert future staff contracts.

Normal runtime: Node 24, PostgreSQL 17, Next/React. Browser tests additionally need Chromium/ffmpeg; native mobile/Safari are not covered by Chromium. CHAT_ENABLED or exact previews govern messaging. Development candidates independently require exact owned DB identity, runtime/actor/configuration and usually Origin checks. CLI workers are manually started (`scripts/chat-analysis-worker.ts`, chat outbox/analysis modules); no general platform scheduler or proven notification delivery is implied. Announcement eligibility is server-time derived; no automatic delivery worker. AI local gateway is numerical loopback Ollama only, synthetic-only; real scoped deterministic Support reads are never forwarded to it. Vision/translation pilots remain mock/hard-disabled live paths; no providers activated by consolidation.

## Model relationships

`User` → `AuthSession`, owned `Listing`, owner/renter `Booking`, conversations/reports/reviews. `Listing` → `ListingMedia`, `ListingStation` → `MrtStation`; `Booking.meetingStationId` preserves the agreement independently of later listing changes. `Booking` → bilateral `Handoff`, `Return`, `BookingEvidencePhoto`, `Dispute`, meetup session/challenge/check-in/event records and `VerifiedReview`. `Conversation`/participants/messages connect rental communication; reviewer/case/outbox/analysis records do not grant rental evidence access. `SupportTicket` → immutable ticket events, participant-private channel/messages, separate from opposing participant channels. Staff person/account/membership/version/grant/history/session/MFA/approval tables are additive, inactive foundations, not production staff activation. Announcements and two typed development display settings have version/event histories. DevItem* → immutable confirmed versions → DevDoc* explicit booking snapshots. DevCondition* and DevRecovery* retain subordinate claim/response/notice/proposal history. Exact FK/unique/relation fields and all remaining models are in the inventory. Preserve original migration bytes; migration replay is tested only in new owned DBs.
