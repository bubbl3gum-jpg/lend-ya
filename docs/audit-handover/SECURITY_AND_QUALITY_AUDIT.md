## Control review

- [Auth](../../lib/auth.ts) issues random session credentials and persists hashes with expiry. Verification uses scrypt, and issuance can be fenced against changed credentials. [Rate limits](../../lib/auth-rate-limit.ts) use shared database state. Upstream throttling and capacity behavior need environment-backed validation.
- Core APIs layer validation with actor, role and booking/listing/participant checks. Chat and Support use independent actors and consent/scopes. [Admin](../../lib/admin) has action-specific validation and audit helpers. [Operational errors](../../lib/operational-error.ts) sanitize responses/logging and assign correlation identifiers.
- Media validation includes bounded multipart reads, decoded image checks, video probing, restrictive response headers and private evidence delivery. Filesystem and database integrity boundaries differ. Verify operational limits under expected upload load.
- [Rental lifecycle](../../lib/rental-lifecycle.ts) uses transaction and row-lock coordination. Booking transition responses distinguish conflict and internal error. The versioned candidate histories and scoped Support schema add database guards beyond application checks. No production credentials, sensitive data or offensive testing were used.
