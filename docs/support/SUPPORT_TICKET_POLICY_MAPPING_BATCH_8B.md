## Technical enablement boundary

Default OFF. Production is refused even if the development flag is accidentally present. Trusted configuration requires NODE_ENV=development, `HUSTLEN_SUPPORT_TICKET_CANDIDATE=owned-development-only`, matching DATABASE_URL/TEST_DATABASE_URL/MRT_TEST_DATABASE_URL, 24-hex ownership run ID, an explicit exact http://localhost:<port> origin, a bounded explicit test quota and server requester-ID allowlist. Effective PostgreSQL target validation rejects query/driver/PG environment overrides except credentials. Service checks actual current_database and exact ownership marker. Database INSERT additionally requires a hustlen_test_* name and a valid ownership marker, independently of the application flag.

The proxy refuses candidate API/pages in production before rendering. Service guards independently refuse before authentication/data queries when configuration is invalid; valid configuration still requires live ownership, current session, ACTIVE status and allowlist. Browser values cannot set these bindings. `/customer-service` retains existing help, reports/disputes guidance and no-live-support statement. Its pilot pointer appears only after ownership verification; candidate subroutes remain inaccessible otherwise. A missing or expired session cannot use a browser role or claimed identity.

This is **not a rollout switch for production**. Do not merge/deploy the candidate migration to an existing application database. No such migration was executed in this batch. Approve the business policies, scoped data access/auditing and a separately reviewed forward production schema/runtime transition first. Never copy synthetic tickets into real user records or automatically convert reports/disputes.
