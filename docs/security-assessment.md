## Dependency advisories and remediation

Actual commands: `npm audit --json`, `npm audit --omit=dev --json`, `npm ls`, `npm view`, and `npm audit fix --dry-run --json`. An initial npm metadata command used the unwritable default cache; it was rerun successfully with `/tmp/lend-ya-npm-cache`. No TLS/checksum verification was disabled.

Initial audit: 10 package entries (9 high, 1 moderate; zero critical). Prisma pinned mysql2 3.15.3 exactly. A scoped `prisma -> mysql2 3.24.6` override is a compatible-major transport dependency update; it resolves the two MySQL advisories without changing Prisma 7.10 or Next 16.3.8. Locked clean installation, Prisma generation/validation, PostgreSQL migrations/build and application suites subsequently passed. The application uses PrismaPg/PostgreSQL and does not expose a MySQL connection workflow; no MySQL functional test is claimed.

Final audit: **9 high advisory-bearing package entries, zero critical/moderate/low**. Runtime-installed audit: **4 high entries**. These are dependency-chain counts, not nine independent vulnerabilities: two advisory roots remain.

Residual advisory chains explain the conditional release gate. Lack of an identified HTTP path is not a guarantee that a dependency is harmless. Do not claim zero vulnerabilities, production hardening or successful hosted CI. Restrict build/DB access, preserve backups and review supported dependency fixes before production exposure.

## Scope limits

Tests cover meaningful known boundary cases and actors, including real concurrent requests and production cookie attributes. Exhaustive fuzzing, reverse-proxy deployment, disaster recovery, browser/codec compatibility beyond the tested environment, operational monitoring, penetration testing and all supply-chain attack modes were not verified. Legacy external condition-photo import and inconsistent historical actor/evidence remediation remain deferred; missing evidence cannot be fabricated. No payment processing, AI judgment or government identity verification was introduced.
