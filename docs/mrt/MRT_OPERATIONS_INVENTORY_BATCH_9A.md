## Actual data and query semantics

`lib/admin/locations.ts:getAdminLocations` authenticates the current ACTIVE legacy ADMIN itself. The API additionally uses existing `adminApi`. The DB query is bounded by all 120 official canonical IDs, selects only persisted id/canonicalId/operational, and takes at most the catalogue size. The official immutable snapshot supplies bilingual names, line membership and public coordinates. No listing/booking/user/evidence counts or personal location records are selected. Validated query filters are q (≤100 characters), exact line and exact station, with unknown/repeated selectors denied.

`globalHandoffEligible` means an official station has a persisted mapping with operational=true. It does not mean the station is live/open/safe, that an owner offers it, or that a particular booking may use it. Missing mapping is explicitly not recorded; false is explicitly globally prevented. A directory line filter preserves interchange membership. The reused network graphic is clearly a schematic; the Lab has a separate north-up metric boundary plot.

Read-only routes: `/admin/locations`, `GET /api/admin/locations`. Both require the existing current-session/ACTIVE ADMIN checks; APIs are private/no-store and vary on Cookie, and pages are dynamic. Lab links appear only for an eligible owned-development tester; production and other Admins see an unavailable explanation instead of a dead link.

## Precise next station-operations change — not authorized here

A future small batch needs additive versioned station-operation state/history with reason, incident/evidence references, scoped proposer/executor identity, effective/revoked time and immutable decisions. Define precedence over catalogue imports so a sync cannot silently clear a safety suspension. Keep official coordinates/catalogue data distinct from operational overrides. Existing meetup verification reads the agreed station/coordinates and does not implement a station-operational suspension gate. A false flag therefore must not be presented as stopping every already agreed meetup. Define safe relocation, challenge invalidation and continued return/inspection/support obligations explicitly before future suspension controls are enabled; never silently rewrite a booking station.

After a separately reviewed real identity/session/scope cutover, approved Operations may immediately suspend an unsafe station only within exact authorized station scope, with durable audit and policy checks. Restoration and sensitive radius/coordinate/geofencing changes require distinct authorized human approval plus a trusted, version-bound executor. Existing approval execution remains blocked; do not treat legacy ADMIN or a dashboard flag as an emergency override. Test assignment/conflict, revocation, catalogue-sync races, stale approvals and effects on existing rental/return/inspection obligations before activation.

This batch creates no schema migration. Read-only production-build acceptance does not make the inherited owned-test Support migrations or the complete branch production-ready. Any future release must independently review deployment/migration provenance; never apply test-only migration history to an existing application database.
