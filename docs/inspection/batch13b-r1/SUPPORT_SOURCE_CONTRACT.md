# Customer Service source readiness — no new access

Existing Support assignment/channel/action/assurance/audit worker remains authoritative and unchanged. A linked ticket or legacy ADMIN flag is not permission to read these new participant tables. New structured Support/Copilot reads remain blocked until exact case capabilities, assignment/participant-conflict rules, allowed fields, audit/evidence access and principal grants are separately approved. No generic transcript/table reader or new service identity is introduced.

Future permitted source mapping:

| Source kind | Actual authority | Required interpretation |
|---|---|---|
| Application fact | Verified receipt/challenge and Booking; durable case/notice event timestamps | Confirms recorded process event, not fault, causation or actual MRT arrival |
| Owner allegation | Immutable DevConditionClaim.original + OWNER_SUPPLEMENT | Attributed claim, not verified damage; supplement cannot rewrite original issue |
| Borrower statement | BORROWER_RESPONSE / BORROWER_CLARIFICATION | Attributed explanation/position/accessory statement; factual agreement is not compensation |
| Notification process | Notice created/queued/view acknowledgement | Not qualifying delivery; test events are explicitly synthetic |
| Agreed disclosure | Exact accepted R2 context/version/hash | Owner declaration acknowledged by participants; not substitute for physical pickup evidence |
| AI observation | Unavailable | No model/vision output exists; never synthesize an observation |
| Human decision | Existing authorized legacy Dispute resolution and immutable AdminAuditLog, if permitted | Require actual persisted actor/time/decision and scoped authorization; do not infer a human approval merely from a generic status |

No new source is connected to a model, external channel or automatic sender. Human-assistance request is a durable borrower statement, not proof of staff assignment/notification. Production Support activation, independent high-risk review, exception/appeal policy and all financial actions remain separately gated.
