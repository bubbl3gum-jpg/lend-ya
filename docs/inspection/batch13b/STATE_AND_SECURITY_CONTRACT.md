# State, deadline, evidence and authorization contract

Owned-development `NODE_ENV=development`, exact `HUSTLEN_INSPECTION_CANDIDATE=owned-preview-only`, identical DATABASE_URL/TEST_DATABASE_URL/MRT_TEST_DATABASE_URL, strict disposable local connection policy, exact run-ID ownership marker from the connected DB, current session and actual Booking.ownerId/renterId. No role shortcut, browser-provided actor/clock/assurance/delivery state or staff provisioning. Production proxy and service refuse independently even configured. Origin and custom CSRF header required for POST; GET accepts only one positive bounded booking selector. Responses are private no-store / Vary Cookie; errors/logs contain no request/evidence/credential bodies.

## Independent state dimensions

- **Physical custody:** RETURN_ACKNOWLEDGED only from bilateral valid pickup, borrower return, matching consumed/completed RETURN challenge verified by actual owner and matching PHYSICAL_RECEIPT_ACK. Authoritative timestamp is original challenge.completedAt. No accepted inspection or status code is substituted. Missing proof → UNCONFIRMED/unavailable, never “not returned” as a proven fact. An acknowledgment is an authenticated application record, not an AI observation or independently established real-world fact.
- **Inspection:** pending/recorded decision and server-derived half-open 24-hour window from that timestamp. Current legacy status must permit inspection; accepted inspection or open dispute blocks new claim preview. An already recorded unacceptable inspection can still prepare a concern within the valid window. Reload/timezone changes never reset the persisted start. An open button reflects the server observation time; POST rechecks eligibility, so a tab cannot extend the deadline.
- **Dispute:** existing real legacy record/status displayed independently. Opening a legacy test dispute changes legacy status, not physical receipt/history. New preview never calls that writer. Structured claim submission remains blocked until immutable typed claims, authorized responses/evidence binding, atomic history/concurrency and lifecycle cutover are designed.
- **Financial:** NOT_IMPLEMENTED. No payment provider, ledger, compensation, automatic liability or deposit deduction.

Owner claim preview requires exact owner, acknowledged return and open standard window. Borrower response preview requires actual borrower, acknowledged return and an existing OPEN opposing-participant dispute. No author/role override. Suspended participants retain these existing rental-obligation reads/previews; no new booking/listing privilege. A fresh real login/logout test confirms subsequent reads denied after revocation. Authorization is re-resolved before preview release; this is not a universal cancellation/erasure claim for previously authorized reads.

## Notification/deadline boundary

No reliable qualifying notification-delivery event exists. Case responseDeadline remains null, preview output notificationDelivered=false and no enforceable 48h timer. `notificationExamples` contains explicit checked-in SYN-* fixture records: one TEST_DELIVERED, one QUEUED, one FAILED, all labelled SYNTHETIC_FIXTURE_NOT_DELIVERY_PROOF. Only the delivered example demonstrates +48h arithmetic; none authorizes enforcement. Missing/failed/queued examples do not start a deadline. They are not bound to a real recipient/dispute and cannot be treated as delivery records. No client notification selector accepted. Silence/expiry has no automatic admission or financial effect.

Future production must define delivery qualification, recipient/dispute/channel/version binding, provider receipts/replay/idempotency, clock authority, failed delivery, retries, exceptions/extensions/appeals, retention and independent human responsibility before activation. Existing composed/queued/private chat messages are not substituted as proof.

## Evidence and data minimization

Reuses BookingEvidencePhoto metadata and unchanged protected `/api/bookings/[id]/evidence/[photoId]`. Every reference identifies booking/stage/uploader/server-recorded time; byte access independently checks session and exact participant. Original pickup/return versus LATER_INSPECTION_RECORD labelled explicitly. Server storage timestamp is not forensic proof of image capture time. Existing booking page exposes permitted original notes/checklists through a direct protected link; no duplicate evidence store or identity data joins.

No upload/replacement operation in the new route. Late supplemental submission is disabled until a separate attributable append-only contract exists; essential existing camera/evidence requirements are untouched. Original file bytes/digests remain unchanged across preview/dispute read sequence in tests. Current listing accessories are explicitly labelled current owner declaration, not an immutable rental inventory. Missing accessory/view is not loss or fault. No automated photo inspection, valuation, Vision AI, identity/biometric data, unrelated case evidence or Support messages.

The read projection is capped at 100 evidence references and 20 latest dispute records, with evidence-cap disclosure; original booking history remains authoritative. UI presents a snapshot with server observation time, not a continuously refreshed guarantee. Claim/response text exists in memory only, not an immutable submission/audit event. Changing booking ID clears drafts. Core operational body is English, consistent with existing rental screens; shell locale/theme remain available. Full Traditional Chinese operational localization, screen-reader/device/visual acceptance remains future work, not claimed complete.
