# Inert Vision and eKYC contracts

`lib/inspection/future-contracts.ts` is provider-independent shape/validation only. No transport, external image transmission, document upload, biometric data, credentials, model inference or activation flag.

Vision inputs: authorized booking, category/checklist and original pickup/return reference IDs/timestamps. Future retrieval must independently authorize each image before export/release and protect originals. Output kinds QUALITY / MISSING_VIEW / POSSIBLE_DIFFERENCE / ACCESSORY_UNCERTAIN require permitted references, bounded text, optional bounded confidence, uncertainty and advisory=true. No liability, cause, repair cost, deduction, tools or action fields. Structural citation validity/confidence are not correctness; human review remains mandatory. `visionInferenceUnavailable` always refuses. Existing evidence is not sent to this interface by the application.

Marketplace identity flow is separate from login and staff passkeys: NOT_STARTED → IN_PROGRESS → VERIFIED or RETRY_REQUIRED / MANUAL_REVIEW / REJECTED; expiry/revocation can later remove eligibility. Exact permitted transitions/retries are policy decisions, not activated code. Proposed result carries country/document type/provider reference and trusted timestamps; no raw document/biometric data in general User/session/listing context. Taiwan supported National ID/ARC versions depend on a reviewed provider; controlled country registry later. Provider-signed result provenance, replay protection, canonical identity/deduplication, expiry/revocation, account binding and transaction-level publish/request fences must be defined before production. A browser “verified=true”, test state or old identity flag must never satisfy authorization. `identityAuthorizationUnavailable` always refuses even a synthetic VERIFIED result; no production eKYC gate is activated here.

Browse/explore remains permitted per product requirements; publish/rental-request eKYC gating is future separately reviewed enforcement. Existing rental/return/Support obligations cannot be removed by a verification rollout. No real ID or liveness material may be collected until lawful processing, provider terms, encryption/access, narrowly scoped reviewers, retention/deletion/incident and accessible alternatives are approved.
